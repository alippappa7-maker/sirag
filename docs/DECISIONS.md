# سجل القرارات المعمارية (Architectural Decisions Log)

هذا الملف يوثق القرارات التقنية والمعمارية التي تم اتخاذها خلال دورة حياة تطوير مشروع "سراج".

## 1. تقنية التطوير (Development Framework)
- **القرار:** استخدام Kotlin Multiplatform / Compose Multiplatform لتطوير التطبيق، والبدء بتطبيق Android.
- **السبب:** التزاماً بتعليمات بناء المشروع الأولية، وتقديم أداء أصلي وسلاسة في استخدام واجهات Jetpack Compose.
- **الاستبعاد:** تم استبعاد تقنية Flutter التي كانت مقترحة سابقاً للحفاظ على اتساق بيئة العمل مع إمكانيات Kotlin المتقدمة في المشروع.

## 2. النماذج وطبقة البيانات (Data Models)
- **القرار:** استخدام `data class` ككائنات غير قابلة للتغيير (Immutable) وتضمين منطق التحقق (Validation) داخل كتلة `init`.
- **السبب:** حماية حالة البيانات من التعديلات غير المتوقعة، وضمان صحة البيانات قبل وصولها لأي طبقة أخرى كقاعدة البيانات أو واجهة المستخدم.

## 3. إدارة السياق (Context Management)
- **القرار:** تبني هيكل توثيقي صارم عبر `PROJECT_CONTEXT.md`، `CHANGELOG.md`، و `docs/DECISIONS.md`.
- **السبب:** منع فقدان حالة المشروع (Context Loss) عند توقف الجلسات، أو نقل المشروع إلى مستودعات Git، أو استخدام منصات مساعدة بالذكاء الاصطناعي أخرى.
